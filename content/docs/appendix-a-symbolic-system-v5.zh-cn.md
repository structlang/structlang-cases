## 第一部分：设计原则

### 核心原则

1. **键盘直接可打**：所有符号都在标准键盘上，无需特殊输入法
2. **层次递进性**：点→线→面→体→主客，符号体现这种递进
3. **可组合性**：低层符号可以组合为高层符号
4. **可操作性**：每个符号都对应明确的分析步骤
5. **边界清晰性**：明确什么能表达，什么不能表达
6. **简洁性**：避免符号过载，保持直观
7. **手写友好性**：简单线条，快速书写

## 第二部分：基础符号表

### 1. 点结构符号

|符号|名称|键盘输入|含义|使用场景|
|---|---|---|---|---|
|`*`|显现点|shift+8|在意图下已显现的对象|标记认知焦点|
|`o`|空点|直接输入o|未显现的对象（背景噪音）|标记被忽略的信息|
|`*+`|正向点|星号+加号|意图期望方向的显现|标记"好/对/要"的对象|
|`*-`|负向点|星号+减号|意图相反方向的显现|标记"坏/错/拒"的对象|
|`*0`|中性点|星号+零|尚未判断正负的显现|标记初次锚定的对象|

**符号规则**：

- 点符号必须与意图绑定：`*[意图]` 或 `*@意图`
- 示例：`*@退货` = 在"退货"意图下的显现点
- 示例：`*狗@退货` = 在退货意图下，狗这个对象显现了

### 2. 线结构符号

|符号|名称|键盘输入|含义|使用场景|
|---|---|---|---|---|
|`=`|线结构|直接输入|单一维度的判断轴|表示一个判断维度|
|`=(+)`|正向线|等号括号加|正向判断落点|标记正向评价|
|`=(-)`|负向线|等号括号减|负向判断落点|标记负向评价|
|`=(+-)`|中间线|等号括号加减|正负之间的落点|标记模糊状态|
|`==>`|线跳变|等等大于|线结构上的跳变|标记判断翻转|

**符号规则**：

- 线符号格式：`对象=(值)[维度]`
- 值范围：-1.0到+1.0之间
- 示例：`商家=(-0.8)[诚信]` = 商家在诚信维度上为-0.8
- 简写：`商家=(-)[诚信]` 或 `商家=-0.8[诚信]`

### 3. 面结构符号

|符号|名称|键盘输入|含义|使用场景|
|---|---|---|---|---|
|`[]`|面结构|方括号|两个维度的交叉|表示二维判断空间|
|`[+ +]`|象限一|方括号加加|(正,正)象限|双正向状态|
|`[+ -]`|象限二|方括号加减|(正,负)象限|冒险/矛盾状态|
|`[- +]`|象限三|方括号减加|(负,正)象限|潜力/等待状态|
|`[- -]`|象限四|方括号减减|(负,负)象限|双负向状态|
|`[]=>[]`|象限跳变|方括号箭头方括号|从一个象限跳到另一个|标记面结构跳变|

**符号规则**：

- 面符号格式：`对象[x, y](维度1 x 维度2)`
- 示例：`项目[+0.7, -0.5](收益 x 风险)` = 高收益高风险项目
- 简写：`项目[+ -](收益x风险)` 或 `项目[+-]`

### 4. 体结构符号（八格）

|符号|名称|键盘输入|对应编码|含义|
|---|---|---|---|---|
|`()`|体结构|圆括号|三维空间中的一格|八格之一|
|`(+ + +)`|全正格|括号加加加|(+,+,+)|理想状态|
|`(+ + -)`|表里不一格|括号加加减|(+,+,-)|能力强但态度差|
|`(+ - +)`|热情缺能格|括号加减加|(+,-,+)|热情但能力不足|
|`(+ - -)`|盲动格|括号加减减|(+,-,-)|盲目行动|
|`(- + +)`|潜力格|括号减加加|(-,+,+)|有潜力待激活|
|`(- + -)`|观望格|括号减加减|(-,+,-)|有能力但消极|
|`(- - +)`|蓄势格|括号减减加|(-,-,+)|态度好但缺条件|
|`(- - -)`|全负格|括号减减减|(-,-,-)|全面缺失|

**符号规则**：

- 体符号标准格式：`对象(A, Q, T)[维度说明]`
- 通用格式：`对象(x, y, z)[维度1, 维度2, 维度3]`
- 示例：`员工(+, -, +)[行动, 素质, 态度]` = 热情缺能格
- 简写：`员工(+-+)` 或 `员工(+ - +)`（推荐带空格）

**重要说明**：

A/Q/T（行动-素质-态度）是**常用但非唯一**的三维选择：

- 评估主体：通常用A/Q/T
- 评估项目：可用(收益, 风险, 周期)
- 评估城市：可用(经济, 环境, 文化)
- **维度必须：相互独立、同一意图、对决策有影响**

### 5. 主客结构符号

|符号|名称|键盘输入|含义|使用场景|
|---|---|---|---|---|
|`<>`|主客结构|尖括号|六维关系快照|**专用于表示双方互动**|
|`主[A,Q,T]`|主体三维|直接输入|主体的行动、素质、态度|标记主方状态|
|`客[A,Q,T]`|客体三维|直接输入|客体的行动、素质、态度|标记客方状态|
|`vs`|对抗关系|直接输入|主客之间的对抗|标记对立博弈|
|`<->`|互动|小于减大于|主客之间的作用|标记一般互动|

**符号规则**：

- 主客符号完整格式：`主(A+, Q+, T+) <> 客(A-, Q+, T-)`
- 简写格式：`主(+ + +) <> 客(- + -)` 或 `主(+++) vs 客(-+-)`
- 示例：`我(+ + +) <> 商家(- + -)` 或 `我(+++) vs 商家(-+-)`

**重要澄清**：

- `<>` **专用于主客结构**，不用于其他用途
- 意图标记使用 `@意图` 或在上下文中说明

### 6. 意图空间符号（新增）

|符号|名称|键盘输入|含义|使用场景|
|---|---|---|---|---|
|`I(t,b,r)`|意图向量|圆括号|T-B-R三维坐标|精确表示意图|
|`@意图`|意图锚点|at+文字|标注当前意图|说明判断依据|
|`T/B/R`|三维轴|直接输入|时间/利益/风险|意图分解|

**三维定义**：

- **T (Time)**：时间取向
    
    - +1：短期取向（追求快速见效）
    - -1：长期取向（追求持久影响）
    - 0：中期平衡
- **B (Benefit)**：利益取向
    
    - +1：自利取向（优先自己利益）
    - -1：利他取向（优先他人福祉）
    - 0：互利平衡
- **R (Risk)**：风险取向
    
    - +1：激进取向（愿意冒险）
    - -1：保守取向（规避风险）
    - 0：适度风险

**符号规则**：

- 完整格式：`I(+1, +1, -1)` = 短期、自利、保守
- 简写：`I(+ + -)`
- 使用：`@退货意图I(+1,+1,-1)` 或 `员工(++-) @项目交付I(+++)`

**示例**：

```
假狗退货：I(+1, +1, -1)  # 快速拿钱，保守
艺术项目：I(-1, 0, +1)   # 长期品质，冒险
意图距离：d = 3.0（不可迁移）
```

### 7. 趋势符号

|符号|名称|键盘输入|含义|使用场景|
|---|---|---|---|---|
|`^`|上升趋势|shift+6|该维度正在增强|预测性增长|
|`v`|下降趋势|直接输入v|该维度正在滑落|预测性下降|
|`->`|稳定趋势|减号大于号|该维度保持不变|预测性稳定|

**符号规则**：

- 趋势必须锚定意图
- 可整体标注：`员工(+ + -)v` = 整体下滑
- 可分维度标注：`员工(A+^, Q+v, T+->)` = 行动上升，素质下降，态度稳定
- 时间框架由意图决定

### 8. 跳变符号

|符号|名称|键盘输入|含义|使用场景|
|---|---|---|---|---|
|`=>`|单向跳变|等号大于号|从旧结构跳到新结构|标记不可逆跳变|
|`\|触发\|`|触发标记|竖线文字竖线|标记引发跳变的事件|说明跳变原因|

**符号规则**：

- 跳变格式：`结构1 |触发| => 结构2`
- 示例：`商家(- + -) |负责人电话| => 商家(+ + +)`
- 触发可简写为：`|事件|` 或直接写事件名

### 9. 时间窗口符号

|符号|名称|键盘输入|含义|使用场景|
|---|---|---|---|---|
|`[T0-T1]`|时间窗口|方括号T数字|结构稳定的持续期|标记一个阶段|
|`@T数字`|时刻快照|at符号T数字|特定时刻的结构状态|标记关键节点|
|`delta`|窗口长度|直接输入|时间窗口的持续时间|标记稳定期长度|

**符号规则**：

- 时间窗口：`[T0-T1]: 结构描述`
- 时刻标记：`@T3: 事件`
- 示例：
    
    ```
    [T0-T3]: 我(+++)-> <> 商家(-+-)-> @T3: |负责人失言| => [T4-T5]: 商家(+++)-> 
    ```
    

### 10. 原点权重符号（新增）

|符号|名称|键盘输入|含义|使用场景|
|---|---|---|---|---|
|`w=数值`|权重|w等号|经验可信度|标记确信程度|
|`原点(w)`|原点权重|括号w|参照系可信度|标记原点强度|
|`~数值`|置信度|波浪号|不确定性|概率判断|

**符号规则**：

- 权重范围：0到1.0
- 结构权重：`结构(+ + -)[w=0.8]` = 80%确信这个状态
- 原点权重：`原点商家[w=0.3]` = 对商家这个参照系30%信任
- 概率表示：`员工(+ - +)~0.7` = 70%把握是这个状态

**示例**：

```
我的叙事：方法A有效[w=0.9]
朋友验证：方法A有效[w=0.6]
他朋友验证：方法A无效[w=-0.5]

权重影响可信度和传播
```

### 11. 视角与分组符号（新增）

|符号|名称|键盘输入|含义|使用场景|
|---|---|---|---|---|
|`[观察]`|虚拟观察位|方括号|第三方视角|外部结构分析|
|`[上:下]`|上下分组|方括号冒号|力量对比|快速判断优劣势|
|`{B-I-G}`|三层压缩|花括号|基础-互动-目标|事件可行性分析|
|`//`|分隔符|双斜线|并行结构|多视角同时呈现|

**符号规则**：

**视角标注**：

```
[观察者视角]:
  A公司(+ + +) vs B公司(- + -)
```

**上下分组**：

```
[上: A公司(+ + +)]
[下: B公司(- + -)]
判断：失衡结构，上方优势
```

**三层压缩**：

```
事件{
  基础层: [++ ]  # 资源充足
  互动层: [+- ]  # 配合不足
  目标层: [- -]  # 目标不明
}
判断：基础好但执行差，不看好
```

**并行表示**：

```
员工(+ + +) @工作 // 员工(- - -) @家庭
同一时刻，不同意图下的不同状态
```

### 12. 网络结构符号（新增）

|符号|名称|键盘输入|含义|使用场景|
|---|---|---|---|---|
|`{节点1, 节点2, ...}`|网络|花括号|多主体集合|群体结构|
|`->`|单向传递|减号大于|影响方向|因果链|
|`<->`|双向互动|左右箭头|相互影响|协作关系|
|`()`|聚类|圆括号|子网络|分组标记|

**符号规则**：

**网络表示**：

```
网络{
  核心(+ + +),
  成员1(- + +),
  成员2(+ - -)
}
```

**传递链**：

```
A(+ + +) -> B(- + -) -> C(- - +)
影响路径：A强势带动B，B影响C
```

**杠杆点识别**：

```
改变B → 最大传递效应
因为B连接多个节点
```

### 13. 向量化表示（新增）

|符号|名称|含义|使用场景|
|---|---|---|---|
|`I·S`|点积|意图与状态匹配度|测量张力|
|`\|S1-S2\|`|向量距离|状态相似度|经验匹配|
|`αI1 + βI2`|向量加法|意图融合|复杂决策|
|`Proj_I(S)`|投影|完成程度|目标追踪|

**符号规则**：

**点积计算**：

```
I = (+1, +1, -1)  # 意图向量
S = (-1, +1, -1)  # 状态向量
I·S = -1+1+1 = 1  # 匹配度
```

**距离计算**：

```
当前状态：S_now
历史案例：S1, S2, S3
d1 = |S_now - S1| = 0.3  ← 最近的案例
d2 = |S_now - S2| = 0.8
d3 = |S_now - S3| = 1.2
→ 调用S1的策略
```

**意图融合**：

```
个人意图：I_p = (+1, +1, -1)
组织意图：I_o = (-1, +1, +1)
实际决策：I = 0.3·I_p + 0.7·I_o
       = (-0.4, 1.0, 0.4)
```

### 14. 辅助符号

|符号|名称|键盘输入|含义|使用场景|
|---|---|---|---|---|
|`:`|描述分隔|冒号|分隔标识和描述|增强可读性|
|`~`|模糊/概率|波浪号|表示不确定性|标记概率判断|
|`#`|注释|井号|添加说明|解释和备注|
|`{}`|分组|花括号|组合多个结构|复杂场景分组|
|`\|`|或|竖线|并列选项|多种可能|
|`&`|与|and符号|同时满足|复合条件|

**符号规则**：

- 注释：`# 这是注释`
- 概率：`员工(+ + -)~0.7` = 70%把握是这个状态
- 分组：
    
    ```
    [T0-T3]: {  我(+++)-> <> 商家(-+-)->  局面稳定}
    ```
    
- 选项：`策略A | 策略B` = A或B
- 复合：`条件1 & 条件2` = 同时满足

## 第三部分：良构公式

### 什么是合法的符号组合

**规则1：点结构必须有意图**

- ✅ 合法：`*@退货` 或 `*狗@退货`
- ❌ 非法：`*` 或 `*狗`（缺少意图）

**规则2：线结构必须有维度和值**

- ✅ 合法：`商家=(-0.8)[诚信]` 或 `商家=(-)[诚信]`
- ❌ 非法：`商家=` 或 `商家=(-0.8)`（缺少维度）

**规则3：面结构必须有两个维度**

- ✅ 合法：`项目[+0.7, -0.5](收益 x 风险)`
- ✅ 合法简写：`项目[+ -](收益x风险)` 或 `项目[+-]`
- ❌ 非法：`项目[+0.7](收益)`（只有一个维度）

**规则4：体结构必须有三个维度**

- ✅ 合法：`员工(+, -, +)[A,Q,T]` 或 `员工(+ - +)` 或 `员工(+-+)`
- ✅ 自定义：`项目(+, -, +)[收益,风险,周期]`
- ❌ 非法：`员工(+ -)[A,Q]`（只有两个维度）

**规则5：主客结构必须有共同意图**

- ✅ 合法：`主(+ + +) <> 客(- + -) @退货`
- ✅ 简写：`主(+++) vs 客(-+-)`（意图在上下文）
- ❌ 非法：`主(+ + +) <> 客(- + -)`（意图不明且无上下文）

**规则6：跳变必须标注触发**

- ✅ 合法：`结构1 |触发| => 结构2`
- ❌ 非法：`结构1 => 结构2`（缺少触发，除非上下文清楚）
- ⚠️ 可接受：如果上下文清楚，可省略

**规则7：时间窗口必须有边界**

- ✅ 合法：`[T0-T3]: 结构描述`
- ❌ 非法：`[T0-?]: 结构描述`（结束边界不明）
- ⚠️ 特殊：当前进行时可写 `[T5-now]:`

**规则8：趋势必须锚定意图**

- ✅ 合法：`员工(+ + -)v @项目交付`
- ✅ 简写：`员工(+ + -)v`（意图在上下文明确）
- ❌ 非法：`员工v`（缺少结构）

**规则9：意图向量必须有三维**

- ✅ 合法：`I(+1, +1, -1)` 或 `I(+ + -)`
- ❌ 非法：`I(+ +)`（缺少R维度）

**规则10：权重必须在合理范围**

- ✅ 合法：`结构[w=0.8]` 或 `结构~0.7`
- ❌ 非法：`结构[w=1.5]`（权重超过1.0）

## 第四部分：推理规则

### 规则1：压缩规则（从点到线）

```
前提：*1@意图, *2@意图, ..., *n@意图
      （多个同意图下的显现点）
      
操作：提取共同维度D
      
结论：对象=(值)[D]
      （形成线结构）
```

**示例**：

```
前提：*1@判断商家 = 商品假
     *2@判断商家 = 无资质
     *3@判断商家 = 态度恶劣
     
操作：提取维度"诚信"
     
结论：商家=(-0.9)[诚信]
```

### 规则2：组合规则（从线到面）

```
前提：对象=(x)[维度1]
     对象=(y)[维度2]
     （同一对象的两个线结构）
     
条件：维度1 ≠ 维度2
     意图统一
     
结论：对象[x, y](维度1 x 维度2)
```

**示例**：

```
前提：项目=(+0.8)[收益]
     项目=(-0.6)[风险]
     
结论：项目[+0.8, -0.6](收益 x 风险)
     -> 在象限[+ -]（高收益高风险）
```

### 规则3：扩展规则（从面到体）

```
前提：对象[x, y](维度1 x 维度2)
     对象=(z)[维度3]
     
条件：维度3 ∉ {维度1, 维度2}
     意图统一
     
结论：对象(x, y, z)(维度1, 维度2, 维度3)
```

**示例**：

```
前提：员工[+0.7, +0.8](行动 x 素质)
     员工=(-0.5)[态度]
     
结论：员工(+0.7, +0.8, -0.5)[A, Q, T]
     -> (+ + -) 表里不一格
```

### 规则4：跳变规则

```
前提：结构1 @T1
     触发事件E @T2 (T2 > T1)
     
条件：张力累积 >= 阈值
     或 外部强制介入
     
结论：结构1 |E| => 结构2 @T2
```

**禁止的跳变**：

- ❌ 无触发的跳变：`结构1 => 结构2`（无上下文时）
- ❌ 逆时间跳变：`@T2 => @T1` (T2 > T1)
- ❌ 跨意图跳变：不同意图下的结构不能直接跳变

**允许的跳变类型**：

**类型1：维度跳变**（同一意图下）

```
商家(- + -) |负责人电话| => 商家(+ + +)
# 行动和态度都翻转，但仍在"退货"意图下
```

**类型2：原点跳变**（意图切换）

```
员工(+ + +) @工作 |家庭危机| => 员工(- - -) @生存
# 意图切换导致整个评估体系改变
```

**类型3：主客跳变**（关系重组）

```
我(+ + +) <> 商家(- + -)
|市长热线威胁|
=>
我(+ + +) <> 商家(+ + +)
# 客方整体翻转
```

### 规则5：窗口规则

```
前提：结构S稳定 @[T0, Tn]
     
条件：无跳变发生
     
结论：窗口W = [T0-Tn]
     delta = Tn - T0（窗口长度）
```

**窗口边界判定**：

- 窗口开始 = 上一次跳变后
- 窗口结束 = 下一次跳变前
- 窗口内部：结构稳定，可小幅波动但不跳变

### 规则6：趋势累积规则

```
前提：结构(A, Q, T)^  # 上升趋势
     持续时间 delta
     
条件：delta >= 临界时间
     或 触发事件出现
     
结论：结构1 |累积完成| => 结构2
     # 趋势转化为跳变
```

**示例**：

```
[T0-T5]: 员工(+ - +)^  # 素质提升趋势
@T6: |培训周期完成| => 员工(+ + +)
# 趋势累积到阈值，发生跨越
```

### 规则7：趋势逆转规则

```
前提：结构v  # 下降趋势
     
条件：有效干预I
     
结论：结构v |干预I| -> 结构^
     # 趋势逆转但未跳变
```

**示例**：

```
[T0-T3]: 员工(+ + -)v  # 态度恶化
@T4: |加薪+晋升|  # 干预
[T4-T6]: 员工(+ + -)^  # 趋势逆转，态度改善
# 注意：用 -> 而非 =>，表示趋势改变而非结构跳变
```

### 规则8：意图匹配规则

```
前提：意图I1 = (t1, b1, r1)
     意图I2 = (t2, b2, r2)
     
操作：计算距离
     d = √[(t1-t2)² + (b1-b2)² + (r1-r2)²]
     
结论：
     d < 0.5  → 高度相似，可迁移
     0.5 ≤ d < 1.0 → 部分相似，需谨慎
     d ≥ 1.0  → 差异大，不可迁移
```

**示例**：

```
退货意图：I1 = (+1, +1, -1)
艺术项目：I2 = (-1, 0, +1)
d = √[4+1+4] = 3.0
结论：不可迁移
```

### 规则9：权重演化规则

```
前提：经验E的初始权重w0
     
操作：每次验证
     - 成功验证：w = w + α(1-w)
     - 失败验证：w = w - β(w+1)
     
其中：α为增强系数（通常0.1-0.3）
     β为衰减系数（通常0.2-0.5）
```

**示例**：

```
初始：方法A有效[w=0.5]
成功验证1次：w = 0.5 + 0.2(0.5) = 0.6
成功验证2次：w = 0.6 + 0.2(0.4) = 0.68
失败验证1次：w = 0.68 - 0.3(1.68) = 0.176

权重影响调用概率
```

### 规则10：网络传递规则

```
前提：节点A影响节点B
     节点B影响节点C
     
条件：A的结构跳变
     
结论：传递路径 A -> B -> C
     传递强度 = wAB × wBC
     
其中：wAB为A到B的影响权重
     wBC为B到C的影响权重
```

**示例**：

```
核心(+ + +) -> 成员1(- + +) -> 成员2(- - +)
        w=0.8           w=0.6

核心跳变到(- - -)：
→ 成员1受影响概率 = 0.8
→ 成员2受影响概率 = 0.8 × 0.6 = 0.48
```

## 第五部分：操作手册

### 从实际情况编码为符号

**步骤1：识别意图**

```
问：我在观察什么？想做什么？
答：确定意图锚点
记录：@意图 或 I(t,b,r)
```

**步骤2：标记显现点**

```
问：在这个意图下，哪些对象进入了我的认知？
答：列出所有相关对象
记录：*1@意图, *2@意图, ...
```

**步骤3：单维判断（线结构）**

```
问：每个对象在关键维度上的判断是什么？
答：逐个维度评估
记录：对象=(值)[维度]
```

**步骤4：多维组合（面/体结构）**

```
问：需要同时考虑几个维度？
答：如果2个->面结构；如果3个->体结构
记录：对象[x, y] 或 对象(x, y, z)[维度说明]
```

**步骤5：主客关系（如果涉及互动）**

```
问：这是我与谁的互动？
答：确定主体和客体
记录：主(A,Q,T) <> 客(A,Q,T) @意图
```

**步骤6：时间标注**

```
问：这个结构从什么时候稳定到什么时候？
答：标记时间窗口
记录：[T0-Tn]: 结构描述
```

**步骤7：趋势判断**

```
问：这个结构正在朝什么方向变化？
答：观察历史和当前信号
记录：结构^ 或 结构v 或 结构->
```

**步骤8：跳变标注（如果发生）**

```
问：什么事件导致结构改变？
答：标记触发因子
记录：结构1 |触发| => 结构2
```

**步骤9：权重评估（可选）**

```
问：我对这个判断有多确信？
答：评估可信度
记录：结构[w=0.8] 或 结构~0.7
```

**步骤10：意图距离（跨场景时）**

```
问：这个经验能用到新场景吗？
答：计算意图距离
记录：d_I = |I1 - I2|
判断：d < 0.5可迁移，d > 1.0不可迁移
```

### 从符号解码为行动策略

**解码规则1：点结构 → 注意力分配**

```
符号：*1@意图, *2@意图, ...
策略：聚焦这些对象，忽略其他
```

**解码规则2：线结构 → 价值判断**

```
符号：对象=(+0.8)[维度]
策略：这个对象在该维度上是强正向，可以依赖
```

**解码规则3：面结构 → 决策方向**

```
符号：对象[+ -]
策略：高收益高风险，谨慎决策或准备后手
```

**解码规则4：体结构 → 人员/事物定性**

```
符号：对象(+ - +)  
策略：热情缺能型，需要培训支持
```

**解码规则5：主客结构 → 博弈策略**

```
符号：主(+ + +) <> 客(- + -)
策略：我方优势，客方推诿，应施加压力
```

**解码规则6：趋势 → 预警和干预**

```
符号：对象(+ + -)v
策略：态度正在恶化，需提前干预，否则可能跳变到更差状态
```

**解码规则7：跳变 → 危机/机会识别**

```
符号：结构1 |触发| => 结构2
策略：识别触发因子，预判跳变方向，提前准备或主动触发
```

**解码规则8：意图向量 → 决策框架校准**

```
符号：I(+1, +1, -1)
策略：这是短期、自利、保守的意图
     决策时优先考虑快速回报和风险控制
```

**解码规则9：权重 → 可信度评估**

```
符号：结构[w=0.3]
策略：这个判断可信度低，需要更多验证
```

**解码规则10：网络结构 → 杠杆点识别**

```
符号：A -> B -> C, B -> D
策略：B是关键节点，改变B影响最大
```

### 检验编码正确性

**检验清单**：

1. **意图一致性检验**
    
    - [ ] 所有符号是否在同一意图下？
    - [ ] 意图是否明确标注（@意图或I(t,b,r)）？
    - [ ] 意图切换是否标记为原点跳变？
2. **层次匹配性检验**
    
    - [ ] 点结构是否有对象和意图？
    - [ ] 线结构是否有维度和值？
    - [ ] 面结构是否有两个维度？
    - [ ] 体结构是否有三个维度？
3. **时间连贯性检验**
    
    - [ ] 时间窗口是否有明确边界？
    - [ ] 跳变是否标注触发？
    - [ ] 时间顺序是否合理（无逆流）？
4. **逻辑自洽性检验**
    
    - [ ] 符号组合是否符合良构公式？
    - [ ] 推理步骤是否符合推理规则？
    - [ ] 是否存在矛盾（如同时+和-在同一维度）？
5. **可解码性检验**
    
    - [ ] 符号能否转化为清晰的行动策略？
    - [ ] 他人能否理解你的符号标注？
    - [ ] 能否用符号重现事件过程？
6. **趋势合理性检验**
    
    - [ ] 趋势判断是否有依据（历史数据/当前信号）？
    - [ ] 趋势的时间框架是否明确？
    - [ ] 趋势与跳变是否区分清楚？
7. **意图匹配性检验**（跨场景时）
    
    - [ ] 是否计算了意图距离？
    - [ ] 距离是否在可迁移范围？
    - [ ] 是否考虑了框架和规范性边界？
8. **权重合理性检验**
    
    - [ ] 权重是否在0-1范围？
    - [ ] 权重是否有验证依据？
    - [ ] 高权重判断是否有足够样本？

### 符号系统能表达什么

**能表达的认知现象**：

1. ✅ 意图聚焦与对象显现
2. ✅ 单维度的价值判断
3. ✅ 多维度的组合判断
4. ✅ 主体与客体的互动关系
5. ✅ 结构的跳变与触发
6. ✅ 时间窗口的切分
7. ✅ 经验结构的压缩
8. ✅ 主观建模的过程
9. ✅ 趋势的预测性判断
10. ✅ 动态演化的过程
11. ✅ 意图的三维空间表示
12. ✅ 经验的权重演化
13. ✅ 多主体的网络互动
14. ✅ 第三方视角观察
15. ✅ 可迁移性的量化判断

**不能表达的现象**：

1. ❌ 无意识过程（只表达显现层）
2. ❌ 纯情绪（情绪需转化为维度评估）
3. ❌ 连续渐变（只表达离散状态和跳变）
4. ❌ 并发多意图（需明确标注或分离）
5. ❌ 无限复杂性（符号强制有限化）
6. ❌ 量子态叠加（必须选择一个状态）
7. ❌ 纯粹的直觉（直觉需要被结构化）
8. ❌ 超越工具理性的价值判断
9. ❌ 深层情感纽带（爱、意义追求）
10. ❌ 系统涌现性质（需要更高理论）

### 符号系统的边界

**适用场景**：

- 决策分析（商业、投资、管理）
- 关系建模（博弈、谈判、协作）
- 事件复盘（项目、危机、冲突）
- 策略规划（竞争、扩张、防御）
- 认知训练（思维、判断、预测）
- 团队沟通（统一语言、减少歧义）
- 案例编码（经验沉淀、知识管理）
- 经验迁移（跨场景复用判断）

**不适用场景**：

- 纯数学推理（应用数学符号）
- 物理过程（应用物理公式）
- 艺术创作（超越结构化）
- 神秘体验（超越可言说）
- 无意识分析（需要其他工具）
- 亲密关系（爱情、亲情、友情）
- 精神追求（意义、价值、信仰）
- 审美判断（美、丑、风格）

**关键原则**：

- 在工具性情境（工作、交易、竞争）用理论
- 在价值性情境（爱、艺术、信仰）放下理论
- 不要把工具理性扩展到所有领域

## 第七部分：扩展机制

### 如何处理悖论性情况

**悖论1：同一对象在同一维度上既+又-**

```
错误：对象=(+0.8)和=(-0.8)[维度]
正确：这是意图未统一导致
      应拆分为：
      对象=(+0.8)[维度] @意图1
      对象=(-0.8)[维度] @意图2
```

**悖论2：跳变没有触发**

```
错误：结构1 => 结构2
正确：必然有触发，只是未识别
      应标注：
      结构1 |未识别触发| => 结构2
      然后继续分析真正触发是什么
```

**悖论3：时间窗口重叠**

```
错误：[T0-T2] 和 [T1-T3] 同时存在
正确：这是多个意图并行
      应分别标注：
      [T0-T2] @意图1: 结构A
      [T1-T3] @意图2: 结构B
```

**悖论4：趋势与跳变混淆**

```
错误：对象(+ + -)=> 或 对象v =>
正确：趋势和跳变要区分
      应标注：
      [T0-T3]: 对象(+ + -)v  # 趋势
      @T3: |触发| => 对象(- - -)  # 跳变
```

**悖论5：意图距离矛盾**

```
错误：相同符号(+++)，不同场景效果完全不同
原因：意图距离过大
正确：先计算意图距离
      I1 = (+1,+1,-1), I2 = (-1,0,+1)
      d = 3.0 > 1.0 → 不可迁移
```

### 如何扩展符号系统

**扩展原则**：

1. 不破坏现有符号的语义
2. 保持层次递进的逻辑
3. 新符号必须有明确操作含义
4. 优先组合现有符号，而非发明新符号
5. 保持键盘可打的约束

**扩展示例**：

**扩展1：群体结构符号**（如需要）

```
新增：{成员1, 成员2, ...} = 群体结构
用法：团队{员工1(+ - +), 员工2(+ + -), ...}
含义：标记多个主体的组合
```

**扩展2：概率/置信度符号**（已纳入）

```
已有：~ = 不确定性标记
用法：对象(+ - +)~0.7
含义：70%的把握是这个状态
```

**扩展3：因果链符号**

```
新增：--> = 因果关系（与->趋势区分）
用法：事件A --> 事件B --> 事件C
含义：标记因果印象链
注意：与 -> (趋势稳定) 区分
```

**扩展4：多维度体结构**（超过3维）

```
新增：(..., ..., ..., ...) = 四维或更多
用法：公司(A+, Q+, T+, R-)[行动, 素质, 态度, 资源]
含义：在特殊需要时扩展维度
警告：一般不推荐，容易过度复杂
```

**扩展5：并行意图标记**（已纳入）

```
已有：// = 并行意图分隔符
用法：对象(+ + +) @意图1 // 对象(- - -) @意图2
含义：同一对象在不同意图下的不同状态
```

**扩展6：可迁移性层级标记**

```
新增：[L层级] = 可迁移性层级
用法：经验A [L+3] = 三层抽象，可迁移
含义：-3到+5层，层级越高越可迁移
```

## 第八部分：符号速查表

### 核心符号（必须掌握）

|符号|名称|含义|示例|
|---|---|---|---|
|`*`|点|显现对象|`*商家@退货`|
|`=`|线|单维判断|`商家=(-)[诚信]`|
|`()`|体|三维状态|`员工(+ - +)`|
|`^`|升|上升趋势|`(+++)^`|
|`v`|降|下降趋势|`(++-)v`|
|`->`|稳|稳定趋势|`(+++)->`|
|`=>`|跳|结构跳变|`(+-+) => (+++)`|
|`\|事件\|`|触发|跳变原因|`\|培训\| =>`|
|`[T-T]`|窗口|时间区间|`[T0-T3]`|
|`@T`|时刻|时间点|`@T3`|
|`@意图`|意图|意图锚点|`@退货`|
|`<>`|主客|双方互动|`主() <> 客()`|

|符号|名称|含义|示例|
|---|---|---|---|

|`~`|概率|不确定性|`(+-+)~0.7`|

|`[观察]`|视角|第三方观察|`[观察者]:`|
|`[上:下]`|分组|上下对比|`[上:A] [下:B]`|
|`//`|并行|多视角|`结构1 // 结构2`|

### 八格速查

|编码|符号|名称|典型特征|
|---|---|---|---|
|1|`(+ + +)`|全正态|理想状态|
|2|`(+ + -)`|表里不一态|能力强但态度差|
|3|`(+ - +)`|热情缺能态|有热情缺能力|
|4|`(+ - -)`|盲动态|盲目行动|
|5|`(- + +)`|潜力态|待激活|
|6|`(- + -)`|观望态|有能力但消极|
|7|`(- - +)`|蓄势态|态度好缺条件|
|8|`(- - -)`|全负态|全面缺失|

### T-B-R意图空间速查

|维度|+1|0|-1|
|---|---|---|---|
|**Time(T)**|短期取向|中期平衡|长期取向|
|**Benefit(B)**|自利取向|互利平衡|利他取向|
|**Risk(R)**|激进取向|适度风险|保守取向|

**常见组合**：

- `I(+1,+1,-1)`：短期、自利、保守（假狗退货）
- `I(-1,0,+1)`：长期、互利、激进（艺术项目）
- `I(0,0,0)`：中性平衡（日常决策）

## 第九部分：常见疑问

### Q1：趋势和跳变怎么区分？

**趋势**：预测性的、渐进的、可能发生的

- 符号：`^` `v` `->`
- 示例：`员工(+ + -)v` = 态度正在恶化（预测）

**跳变**：断点式的、突变的、正在/已经发生的

- 符号：`=>`
- 示例：`员工(+ + -) |当众批评| => 员工(- - -)` = 已经跳变

**关键**：趋势在时间窗口内持续，跳变标志窗口边界。

---

### Q2：趋势对应的时间范围？

取决于意图的时间框架：

- 项目交付（看"周"）：`员工(+ + -)v @本季度`
- 战略发展（看"年"）：`公司(+ + +)^ @未来3年`
- 日常管理（看"天"）：`士气(+ + -)v @本周`

没有固定标准，由分析者根据意图确定。

---

### Q3：符号系统能处理多个意图吗？

可以，但需要明确标注。

**方法1：时间分离**

```
[T0-T2] @工作: 员工(+ + +)->
[T2-T4] @家庭: 员工(- - -)v
```

**方法2：并行标注**

```
员工(+ + +) @工作 // 员工(- - -) @家庭
# 同一时刻，不同意图下的不同状态
```

核心原则：意图必须明确，避免混淆。

---

### Q4：体结构必须是A/Q/T吗？

不是。A/Q/T只是标准模板。

**可以自定义三维**：

```
项目(收益+, 风险-, 周期+)
候选人(专业+, 沟通-, 稳定+)
城市(经济+, 环境-, 文化+)
```

**原则**：

- 三个维度必须相互独立
- 必须在同一意图下有意义
- 必须对决策有影响

推荐：大多数人际/组织场景用A/Q/T，其他场景自定义。

---

### Q5：符号系统有学习曲线吗？

有，但不陡峭。

**新手路径**：

- **第1小时**：学会体结构 `(+ + +)` 和基本趋势 `^ v ->`
- **第2小时**：学会跳变 `=>` 和触发 `|事件|`
- **第3小时**：学会主客结构 `主() <> 客()`
- **第4小时**：学会时间窗口 `[T0-T3]`
- **第5小时**：综合应用，分析真实案例

3小时基本上手，10小时熟练，30小时精通。

能，而且很适合。

**优势**：

- 统一语言，减少歧义
- 结构化讨论，提高效率
- 可视化呈现，便于理解
- 可沉淀为文档，便于复盘

**建议**：

### Q7：符号系统会不会过度简化？

会，但这是必要的。

**为什么要简化**：

1. 人脑处理能力有限
2. 决策需要在有限时间内完成
3. 复杂性会导致分析瘫痪

**如何平衡**：

1. **核心用符号**：关键结构、主要跳变
2. **细节用文字**：补充说明、背景信息
3. **组合使用**：符号勾勒骨架，文字填充血肉

### Q8：意图向量怎么计算？

**步骤1：分解意图**

```
意图：快速完成项目，获得收益，控制风险
→ T = +1 (快速=短期)
→ B = +1 (获得收益=自利)
→ R = -1 (控制风险=保守)
结果：I(+1, +1, -1)
```

**步骤2：计算距离**

```
意图1：I1 = (+1, +1, -1)
意图2：I2 = (-1, 0, +1)
d = √[(1-(-1))² + (1-0)² + (-1-1)²]
  = √[4 + 1 + 4] = 3.0
```

**步骤3：判断可迁移性**

```
d < 0.5：高度相似，可迁移
0.5 ≤ d < 1.0：部分相似，需谨慎
d ≥ 1.0：差异大，不可迁移
```

---

### Q9：<>符号到底是什么用途？

**明确定义**：`<>` **专用于主客结构**

**正确用法**：

```
主(+ + +) <> 客(- + -)
我(+++) <> 商家(-+-)
```

**错误用法**：

```
<退货>  # 这是意图，应该用 @退货
<意图>  # 同上
```

**意图标记正确方式**：

```
@退货
@意图名称
I(+1,+1,-1)
```

---

### Q10：权重和概率有什么区别？

**权重 `[w=数值]`**：

- 表示经验的可信度
- 来自验证频率
- 随时间演化
- 示例：`策略A有效[w=0.8]` = 这个经验被验证过很多次

**概率 `~数值`**：

- 表示判断的不确定性
- 来自当前信息不足
- 是一次性评估
- 示例：`员工(++-)~0.7` = 70%把握是这个状态

**使用场景**：

- 权重：用于经验库、案例库、结构辞
- 概率：用于当前判断、实时分析、临时评估

### 常见错误与纠正

**错误1：符号过度复杂**

```
❌ 错误：*[意图1]∩*[意图2]∪o[背景]&员工(+,-,+)~0.7^...
✅ 正确：先确定单一意图，简化分析
        员工(+ - +)^ @核心意图
```

**错误2：缺少时间标注**

```
❌ 错误：员工(+ - +) => 员工(+ + +)
        （什么时候跳的？）
✅ 正确：@T3: 员工(+ - +) |培训完成| => 员工(+ + +)
```

**错误3：混淆趋势和跳变**

```
❌ 错误：员工(+ + -)=> 或 员工v =>
✅ 正确：[T0-T3]: 员工(+ + -)v  # 趋势
        @T3: |触发| => 员工(- - -)  # 跳变
```

**错误4：混淆不同意图**

```
❌ 错误：在@工作意图下使用@家庭维度
✅ 正确：保持意图统一，或明确切换
        [T0-T2] @工作: ...
        [T2-T4] @家庭: ...
```

**错误5：符号堆砌无逻辑**

```
❌ 错误：员工(+ - +) 商家(- + -) 项目[+ -] ...
        （这些东西什么关系？）
✅ 正确：说明结构之间的关系
        员工(+ - +) 负责 项目[+ -]
        或
        我(+ + +) <> 商家(- + -) @交易
```

**错误6：意图不明确**

```
❌ 错误：对象(+ + +)
        （什么意图下的+++？）
✅ 正确：对象(+ + +) @项目交付
        或在上下文中说明意图
```

**错误7：<>符号误用**

```
❌ 错误：<退货> 或 <意图>
✅ 正确：@退货 或 I(+1,+1,-1)
        <>专用于主客结构
```

## 第十一部分：高级应用

### 向量化分析

**点积计算：测量张力**

```
意图：I = (+1, +1, -1)
状态：S = (-1, +1, -1)
点积：I·S = -1+1+1 = 1

解读：中等张力，系统有改变压力但可控
```

**距离计算：经验匹配**

```
当前：S_now = (+0.5, -0.3, +0.7)
案例1：S1 = (+0.6, -0.2, +0.8), d1 = 0.17
案例2：S2 = (-0.3, +0.4, -0.5), d2 = 1.32

选择：调用案例1的策略（距离最近）
```

**向量加法：意图融合**

```
个人：I_p = (+1, +1, -1)
组织：I_o = (-1, +1, +1)
实际：I = 0.3·I_p + 0.7·I_o = (-0.4, 1.0, 0.4)

解读：实际决策偏向组织意图
```

**投影计算：完成度**

```
目标：I = (+1, +1, -1)
当前：S = (+0.5, +0.8, -0.5)
投影：Proj_I(S) = 0.6

解读：60%完成度，继续当前策略
```

### 网络分析

**传递链识别**

```
网络{
  A(+ + +) -> B(- + -) -> C(- - +)
       w=0.8         w=0.6
}

A跳变到(- - -)：
→ B受影响概率 = 0.8
→ C受影响概率 = 0.48
```

**杠杆点识别**

```
关键节点判断：
- 连接数最多
- 传递权重最高
- 位置最中心

改变关键节点 → 最大系统影响
```

### 可迁移性分析

**九层判断框架**

```
Layer -3: 完全不可迁移（框架冲突）
Layer -2: 高风险迁移（规范性问题）
Layer -1: 需大量调整（结构差异大）
Layer 0:  可尝试（需验证）
Layer +1: 基本可迁移（小调整）
Layer +2: 较容易迁移（直接应用）
Layer +3: 高度可迁移（模式级）
Layer +4: 很容易迁移（原则级）
Layer +5: 极易迁移（元原则）

判断依据：
1. 意图距离：d_I < 0.5
2. 框架一致性
3. 规范性边界
4. 结构同态性
```

## 总结

### 符号系统的本质

这套符号系统是**认知地图的标注语言**：

1. `*` **点符号**：标注注意力焦点
2. `=` **线符号**：标注价值判断
3. `[]` **面符号**：标注二维组合
4. `()` **体符号**：标注三维状态
5. `<>` **主客符号**：标注关系结构
6. `^ v ->` **趋势符号**：标注动态预测
7. `=>` **跳变符号**：标注断点变化
8. `[T-T]` **时间符号**：标注稳定周期
9. `I(t,b,r)` **意图向量**：标注决策框架
10. `[w=]` **权重符号**：标注可信程度

### 核心价值

**对个人**：

- 清晰思考工具
- 决策分析框架
- 认知训练方法
- 经验沉淀载体
- 可迁移性判断工具

**对团队**：

- 统一沟通语言
- 结构化讨论工具
- 案例编码标准
- 集体智慧积累
- 组织记忆系统

**对研究**：

- 模式识别基础
- 理论验证工具
- 跨案例比较方法
- 经验规律提炼
- 认知科学应用

### 使用原则

1. **简洁优先**：用最简单的符号表达最清晰的思想
2. **意图明确**：所有分析都要锚定意图（@意图或I(t,b,r)）
3. **时间标注**：重要事件必须有时间窗口
4. **权重记录**：经验要标注可信度
5. **距离计算**：跨场景前计算意图距离
6. **持续修正**：符号系统在使用中不断完善
7. **工具而非目的**：符号是为了看清结构，不是为了炫技
8. **边界意识**：知道什么能用、什么不能用

### 最后的话

符号系统的价值在于：

1. 帮你看清结构
2. 帮你记录过程
3. 帮你沟通思考
4. 帮你积累经验
5. 帮你判断可迁移性
6. 帮你理解认知本质

**记住**：

- 符号是工具，不是目的
- 简洁比复杂更有力量
- 实用比完美更重要
- 行动比符号更关键
- 在工具性情境用理论
- 在价值性情境放下理论
